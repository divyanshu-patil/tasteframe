# Product and Technical Requirements

## Product
**Working name:** Tasteframe. Upload a photo and receive Story designs and music suggestions shaped by visual mood and cultural taste.

**Primary user:** Someone who wants a polished Instagram Story without starting from a blank canvas.

**Differentiator:** Qloo returns cultural evidence that changes recommendations. It is not just mentioned in the product description.

## MVP user journey
1. Open web app without mandatory sign-in.
2. Upload JPEG/PNG/WebP.
3. Review visual cues or select mood manually.
4. Add favorite artists/films/brands or other supported Qloo entities.
5. Confirm entity matches.
6. Generate three layouts and music recommendation.
7. Inspect “why this was suggested.”
8. Edit text/layout and export 1080×1920 PNG.
9. Optionally clear session/upload.

## Functional requirements

### FR-01 Upload
- Support JPEG, PNG, WebP.
- Initial size limit: 10 MB, configurable.
- Validate MIME, size and actual image decoding server-side.
- Preview, replace and remove image.
- Do not trust filename extension or client-only validation.

### FR-02 Taste inputs
- Accept optional user-entered cultural seeds.
- Resolve via supported Qloo entity search/lookup.
- Present disambiguation choices.
- Never treat a plain string as a resolved Qloo ID.
- Do not infer personal cultural taste from a photo alone.

### FR-03 Visual profile
- Extract broad palette, lighting, composition and mood labels.
- Manual mood controls work if vision is unavailable.
- No face recognition or sensitive attribute inference.
- Vision provider is optional and isolated behind an adapter.

### FR-04 Qloo
- Calls only from FastAPI.
- Use currently documented, account-enabled endpoints and parameters.
- Normalize provider responses.
- Distinguish Qloo results from vision labels and local template rules.
- Handle invalid key, timeout, rate limit, empty result and malformed response.
- Never label hard-coded/demo data as live Qloo output.

### FR-05 Layouts
- Return at least three distinct layout IDs for valid inputs.
- Each has a name, rationale, style tags and editable config.
- Layouts are rendered locally, not generated by Qloo.
- Keep text contrast and safe margins for Instagram UI.
- Fixed 9:16 canvas; export 1080×1920.
- Allow user override regardless of ranking.

### FR-06 Music
- Display a track title only when metadata is verified.
- If Qloo returns only an artist, label it as artist-level.
- Do not invent track names, popularity, scores or URLs.
- Do not download or redistribute copyrighted audio without rights.
- Where available, instruct users to add audio through Instagram's native music sticker.

### FR-07 Editor/export
- Edit caption/headline, font size, position, alignment, color and overlays.
- Reset to template.
- Export PNG at exactly 1080×1920 without paid image API.
- Source image crop/contain/cover behavior is explicit.
- Export errors have retry path.

### FR-08 Persistence (optional)
- Save only with clear intent.
- Do not persist source photos by default.
- If saved stories exist, support database and S3 deletion.
- Enforce Supabase RLS.

### FR-09 UX/accessibility
- Responsive mobile/desktop.
- Loading, error, retry, empty and success states.
- Accessible labels, keyboard navigation and focus indicators.
- No indefinite spinner on provider outage.

## Technical requirements
- Root: pnpm + Turborepo.
- `apps/web`: Next.js App Router + TypeScript.
- `apps/api`: FastAPI + Pydantic + `httpx` + `boto3`; pytest and Ruff.
- `packages/ui`: shared primitives only when useful.
- Canvas/SVG rendering; avoid paid image-generation APIs.
- Python dependencies use a venv and `pyproject.toml` or pinned `requirements.txt`.
- API contracts in `docs/api-contracts.md`.

## Security
- `.env` files ignored; `.env.example` contains placeholders only.
- Qloo/AWS/Supabase service-role credentials server-only.
- Private S3 bucket, Block Public Access, random keys, short-lived presigned URLs.
- Strict CORS allowlist, request limits, rate limiting and timeouts.
- RLS for user-owned Supabase records.
- Strip EXIF/GPS where practical.
- No secrets, signed URLs or raw images in logs.
- Support deletion and temporary-object expiry.

## Performance/reliability targets
- Measure rather than assume performance; target under 10 seconds p95 for typical uploads, excluding cold-start delays.
- Explicit external request timeouts.
- Bounded retries only for transient failures.
- Avoid duplicate Qloo calls for identical inputs when caching is allowed.
- Editor/export must work after recommendations load, without further external API calls.

## Cost constraints
- Qloo is the only intentionally paid API.
- Free tiers/local models are optional and quota-limited; check terms and data policies.
- S3, hosting, egress and database usage may cost money beyond free allowances.
- Use budget alerts, upload limits and lifecycle deletion.

## Out of scope
- Automatic Instagram posting/private API access.
- Audio redistribution without rights.
- Face recognition/sensitive inference.
- Guaranteed virality predictions.
- Claiming Qloo analyzes pixels or renders layouts.
- Social features/video generation before MVP is stable.
